### 핵심 결론 3가지

1. **병목은 모델이 아니라 서빙이다.** GPU 사용률 28%, 토큰당 30ms, 작업자 1개, 문장을 끝까지 합성한 뒤에 재생 [문서]. 같은 모델을 쓰는 최적화 엔진은 훨씬 빠르다고 보고돼 있다(GSV-TTS-Lite: RTX 3050 노트북에서 첫 패킷 133ms, RTF 0.108 [조사], 프로젝트 자체 보고).
2. **가장 큰 레버는 4가지다.** ① CUDA Graph 엔진 ② 토큰 스트리밍 ③ 연속 배치 ④ 첫 문장을 일찍 자르기. 다만 **GSV-TTS-Lite는 한국어를 지원하지 않는다** [조사]. 한국어 전처리를 이식하고 음질이 같은지 확인하는 것이 이 계획의 가장 큰 위험이자 핵심 작업이다.
3. **지금은 Vercel 무료 + 오리진 직결로 충분하고, Cloudflare는 선택이다.** 도메인이 없어도 `*.vercel.app`과 `rewrites`로 `/api`를 오리진에 연결할 수 있다. Cloudflare Containers에는 GPU가 없어서 계산을 맡길 수 없다 [조사]. GPU는 임대 서비스(3절)를 쓰고, 집 PC는 개발과 고도화에 쓴다.

## 2. 목표 아키텍처

```
[브라우저]
   │  HTTPS: 정적 파일 + /api/* (HTTP 스트리밍)
   ▼
[Vercel 무료]  web/ 정적 파일 + rewrites(/api/* → 오리진 주소)     ← 도메인 없이 *.vercel.app
   │
   ▼  오리진 주소만 바꾸면 집 PC ↔ 임대 GPU 전환 (vercel.json 수정 + 재배포 1회)
[오리진]  집 PC(Tailscale Funnel, 지금 쓰는 방식) 또는 임대 GPU(서비스가 주는 공개 주소)
   ├─ 오케스트레이터 (FastAPI/asyncio, 8801 상당)
   │    ├─ 동의 확인 · 속도 제한 · 동시 세션 상한 · 예산 퓨즈   ← 안전장치는 오리진 안에 둔다
   │    ├─ 즉시 리액션 (기존)
   │    ├─ Gemini 스트리밍 → 문장 단위 분할 → 합성 직전 문장 검사(가드레일)
   │    └─ TTS 요청 → 엔진 (연속 배치 + CUDA Graph + 토큰 스트리밍)
   ├─ TTS 엔진 (한국어 전처리 포함) → PCM 청크
   ├─ STT (서버 경로용 faster-whisper)
   └─ 8800(로컬 전용 `/v1/*`)은 **밖으로 노출하지 않는다**

(선택, 나중에) Cloudflare Worker 게이트웨이 + Turnstile: 도메인이 생기거나 봇 방어가 필요해질 때
```

- **안전장치는 오리진 안에 둔다.** 계정과 도메인 없이 가능하다. 컨테이너가 1개인 동안은 프로세스 안 카운터로 충분하고, 여러 개로 늘릴 때만 공유 저장소가 필요하다.
- **현재 페이지가 이미 이 경로(Vercel rewrites → 오리진)로 NDJSON을 스트리밍하고 있다** [문서]. 오디오 스트리밍도 같은 경로를 쓴다.
- Vercel 무료(Hobby)는 비상업용이라는 약관이 있는 것으로 알고 있다 [가정: 확인 필요, 5.9].

### 설계 원칙 (바꾸지 말 것)

1. **임의 문장을 마젯 목소리로 읽게 하는 API는 만들지 않는다.** TTS의 텍스트는 서버가 만든 답변에서만 나온다 [문서: 사칭 방지]. 새 스트리밍 규약에서도 클라이언트가 TTS에 텍스트를 보낼 수 없다.
2. **목소리 가중치는 비공개 저장소에만 둔다.** GitHub, 공개 R2 버킷에 올리지 않는다 [문서]. 서비스로 들려주는 것과 모델 파일을 배포하는 것은 별개다.
3. **품질은 숫자보다 사용자 귀가 우선**이다 [문서]. 엔진을 바꿀 때마다 블라인드 청취를 거친다.
4. **언제든 옛 경로로 되돌릴 수 있게** 한다(6절).
5. **마젯 목소리임을 밝히고(동의 문구), 외설적이거나 폭력적인 사용은 서버 가드레일로 막는다.** 이용자에게 보이는 것은 동의 문구뿐이고 신고 창구는 두지 않으므로, **가드레일이 사실상 유일한 방어선**이다(10절). 조건을 어기면 미츄 회사와 법적 분쟁이 생길 수 있다는 것이 사용자의 설명이다.
6. **예산이 먼저다.** 최종 30명, 월 3만 원 안에서 설계한다. 비용이 한도에 닿으면 서비스가 정중하게 멈추는 구조(예산 퓨즈, 자동 종료)를 기능보다 먼저 만든다.

### 한 턴의 지연 예산 (채팅 입력 경로, 목표, 측정 전)

기준 시각 0 = **채팅이 서버에 도착한 시점**이다. 받아쓰기 시간은 포함하지 않는다. 음성으로 말하면 브라우저 인식 약 0.3초 / 서버 인식 0.8~1.5초가 앞에 더해진다.

| 구간 | 누적 목표 | 비고 |
|---|---|---|
| 즉시 리액션 시작 | 0.15초 | 미리 만든 wav [문서: 0.1초 안팎]. **KPI에는 넣지 않는다** |
| Gemini 첫 토큰 | 0.4~0.8초 | [가정] 측정 필요 |
| 첫 절 완성(쉼표 또는 8~12자에서 먼저 자름) | 0.6~1.1초 | Phase 1.3 |
| TTS 첫 음성 조각 | 1.0~1.5초 | Phase 2~3. GSV-TTS-Lite 133ms 보고 [조사] |
| 네트워크 + 재생 버퍼(120~200ms) | **1.2~1.9초** | 지역(RTT)에 따라 다름 |
| **첫 답변 음성** | **약 1.2~1.9초** | 2초 내외 목표를 충족하지만 **여유가 크지 않다** |

현재 방식(문장을 끝까지 합성한 뒤 재생)은 약 2.5~3.5초로 추정된다 [가정]. 2초 목표는 **Phase 1.3(첫 조각 짧게)과 Phase 3(스트리밍) 없이는 어렵다.** 또 임대 GPU가 한국에서 멀면 RTT가 0.1~0.3초를 더하므로 3절에서 리전을 고르고 6.4에서 측정한다.

### 전송 규약 (HTTP 스트리밍이 기본, WebSocket은 선택)

- **기본: HTTP 스트리밍.** Vercel rewrites를 그대로 쓰고, 오디오도 `fetch()`의 `ReadableStream`으로 조각을 받는다.
  - `POST /api/chat` → 줄 단위 JSON(`start`, `text`, `emotion`, `seg`, `done`). 기존과 같다.
  - `GET /api/speech?r&i` → **청크로 흘러오는 PCM16 모노 오디오.** 기존에는 문장 하나를 통째로 응답했다. 첫 조각이 준비되는 대로 보낸다.
  - 끼어들기: 클라이언트가 해당 `fetch`를 `abort()`하면 서버가 연결 끊김을 감지해 합성을 즉시 멈춘다. 감지가 느리면 `POST /api/cancel`을 보조로 둔다.
- **WebSocket은 선택.** Vercel rewrites가 WebSocket을 중계하는지 확인하지 못했다. 쓰려면 클라이언트가 오리진에 직접 붙거나 Cloudflare Worker를 거쳐야 한다. 필요해지면 `hello`, `user_text`, `cancel`, `ping` / `audio_begin`, 바이너리 프레임, `audio_end`, `done`으로 확장한다.
- **유휴 100초 제한:** Cloudflare 경유 연결은 100초 동안 데이터가 없으면 끊기고(Free/Pro/Business는 변경 불가) [조사], RunPod의 HTTP 프록시도 같은 제한이 있다 [조사]. HTTP 스트리밍은 데이터가 계속 흘러서 영향이 작지만, 유휴 구간에는 20~30초마다 하트비트를 보낸다.
- 오디오는 PCM16 모노로 시작한다. **대역폭:** 24kHz[가정] PCM16은 한 명당 약 48KB/s(약 0.4Mbps)라서 30명이면 약 11Mbps다 [계산]. 집 업로드 회선과 Tailscale Funnel(대역폭 한도가 비공개 [조사])이 병목이 될 수 있으므로, 규모를 키우기 전에 Opus 같은 압축을 검토한다. 임대 GPU에서는 이 문제가 작다.
- 기존 NDJSON + `/speech?r&i` 경로는 **폴백으로 유지**한다.

## 3. 컴퓨트 배치와 임대 GPU 조사

### 운영 구조 (사용자 결정)

- **집 PC:** 개발, 측정, 고도화, 소규모 사용. 지금처럼 Tailscale Funnel로 공개한다. 추가 비용 없음.

### 추천

1. **1순위: Modal.** 무료 크레딧으로 비용 없이 시험할 수 있고, 유휴 과금이 없고, FastAPI와 WebSocket을 지원해서 우리 구조와 맞는다. 6a에서 현재 엔진을 올려 **콜드 스타트, 한국 RTT, 첫 음성 시간**을 먼저 잰다.
2. **2순위: RunPod Secure Cloud Pod.** 행사가 길거나, Modal의 지연·한도가 문제일 때. 시간당 가장 싸지만 끄는 것을 잊지 않게 자동 종료를 건다.
3. **Hugging Face Spaces**는 비공개로 설정할 때만, 지인용 데모 정도로 쓴다.
4. **Cloudflare는 이 계산 자리에서는 쓰지 못한다.** 나중에 도메인이 생기면 입구(5B)로만 쓴다.

### 비용 감각 (월 3만 원 + Modal 무료 크레딧)

- Modal 무료 크레딧 $30는 L4 기준 약 37시간이다(GPU 요금만 환산, CPU·메모리가 별도라 실제는 더 적다) [계산, 검증 필요].
- 3만 원은 달러당 1,400원이면 약 $21이고 L4 기준 약 27시간이다 [계산].
- 합치면 **월 60시간 안팎이 이론상 상한**이고, 3시간짜리 행사로 월 약 20번 분량이다. 요금이 실제로 이 값인지 확인하기 전까지는 어림값이다.

### 개발·배포 흐름

- 모델 파일(학습 모델, Whisper, 말투 모델, 리액션)은 임대 서비스의 **비공개 볼륨**에 한 번 올린다(수 GB~수십 GB, 업로드 시간은 회선에 따라 다름).
- 집 PC에서 고도화 → 안정판에 태그 → 임대 GPU에 반영(이미지 또는 볼륨 갱신).
- 임대 GPU 쪽 환경은 CUDA 12.8 계열을 맞춘다(GSV-TTS-Lite 요구 [조사]).

### 지역과 지연

- 한국에서 서버까지의 RTT가 첫 음성 시간에 직접 더해진다. 요청과 첫 오디오 조각까지 왕복이 몇 번 필요하므로 **RTT 150~250ms[가정]인 리전이면 예산(0.2~0.4초)을 거의 다 쓴다.** 2초 목표의 위험 요소다.
- 아시아 리전(도쿄, 싱가포르 등)을 고를 수 있는지는 서비스별로 확인 필요. 6.4에서 한국 폰과 가정 회선으로 실제 측정한다.
- **VRAM 가늠(가정):** GSV-TTS-Lite는 원본(1.6GB) 대비 0.8GB 보고 [조사]. Whisper large-v3 int8_float16이 수 GB. 16~24GB GPU(L4 등) 한 장에 TTS 여러 작업자와 STT가 들어갈 가능성이 높다. Phase 0에서 실측한다.

**합격(제안):** 유사도 0.80 이상, 발음 오류 3% 이하, 블라인드에서 기준(조합 D)과 같거나 더 낫다는 사용자 판정, 토큰당 시간 절반 이하.

**결정 게이트(시간 상자 3~5일):** 이식이 합격하지 못하면 **2B**로 전환한다.
- **2B: 원본 엔진을 직접 가속.** AR 디코더에 정적 KV 캐시와 고정 길이 구간(버킷)을 두고 CUDA Graph로 캡처한다. `torch.compile(mode="reduce-overhead")`는 Triton이 필요한데 **공식 Triton이 Windows를 지원하지 않는다** [조사]. WSL2/리눅스 도커에서 하거나 커뮤니티 `triton-windows`를 쓴다. 수동 `torch.cuda.CUDAGraph` 캡처는 Windows에서도 가능하다 [가정]. 난이도가 높아 최후 선택.
- 이 경우에도 Phase 3(스트리밍), Phase 4(배치) 설계는 그대로 쓴다.

**참고:** CUDA Graph는 일반 LLM 추론에서 2.3배 가속 사례가 있다 [조사]. 같은 구조의 AR TTS에 vLLM을 적용해 GPT 디코딩이 약 3배 빨라졌다는 사례(IndexTTS) [조사]도 있다. 두 숫자 모두 다른 모델의 사례라서 우리 모델에 그대로 기대하면 안 된다.

### Phase 3 — 토큰 스트리밍 + 웹 스트리밍 재생 (M)

**목표:** 문장 전체를 기다리지 않고, 첫 조각이 나오는 순간 재생을 시작한다.

### Phase 4 — 동시성: 연속 배치, 스케줄러, 취소 (L)

**왜 효과가 클 것 같은가(가정):** AR 디코딩은 단계마다 메모리를 읽는 일이 대부분이라 요청 8개를 묶어도 한 단계 시간이 거의 늘지 않는다. 지금은 GPU가 28%만 쓰이고 있어서 묶으면 처리량이 크게 늘 여지가 있다. 원본 README의 높은 처리량 수치도 병렬 추론 조건이다 [조사].

| ID | 작업 | 담당 |
|---|---|---|
| 4.1 | **빠른 이득:** 합성 작업자 N개(프로세스) + 최소 부하 배정. 작업자 하나의 VRAM이 작으면(0.8GB 보고) 한 GPU에 3~4개가 들어간다 [가정] | 로컬 |
| 4.2 | **엔진 연속 배치:** 요청이 매 디코딩 단계마다 배치에 들어오고 나가게 한다. 선채움(prefill)은 분리. 배치 크기 상한 B는 부하 시험으로 정한다. GSV-TTS-Lite의 `infer_batched()`/연속 배치 기능 활용 가능 [조사] | 로컬 |
| 4.3 | **디코더(보코더) 큐 분리:** 여러 요청의 조각을 모아 SoVITS 디코딩을 배치하고, 토큰 생성과 겹쳐서 실행(별도 CUDA 스트림/스레드) | 로컬 |
| 4.4 | **우선순위:** 첫 조각과 즉시 리액션 > 이후 조각. 한 사용자가 독점하지 못하게 세션별 공정성 | 로컬 |
| 4.5 | **취소와 역압:** `cancel`이 오면 다음 단계에서 배치에서 제거. 대기열은 상한을 두고, 넘치면 `busy` + 재시도 안내를 보내서 화면에 "잠깐 줄 서는 중"을 표시 | 로컬 + 클라우드(UI) |
| 4.6 | **수용량 공개:** `/healthz`에 `capacity`, `queue_depth`, `p95_ttfa`를 노출. 게이트웨이와 UI가 사용 | 로컬 |
| 4.7 | **부하 시험기:** 가상 사용자 N명이 채팅을 보내고 오디오 스트림을 받는 스크립트(`dev/loadtest/`). 가짜 서버로 먼저 만들고, 실제 서버에서 로컬이 실행 | **클라우드**(작성) + 로컬(실행) |

**목표 해석(가정):** "동시 접속 30명"은 30명이 동시에 합성을 요청한다는 뜻이 아니다. 대화 중에는 사용자가 말하고, 생각하고, 마젯이 말하는 시간이 번갈아 오므로, **동시에 합성 중인 수 ≈ 접속자 × 마젯이 말하는 시간 비율(약 0.3~0.4 가정) ≈ 9~12명**이다. 이 비율은 부하 시험기에 현실적인 말하기·듣기 주기를 넣어서 실제로 확인한다.

**합격(제안, 단계별):** **3명 → 10명 → 30명(최종)** 순서로 같은 시험을 반복한다. 30명 단계는 가상 사용자 30명(현실적인 주기, 동시 합성 약 10)에서 첫 답변 음성 p95가 단독 p50의 2배 이내, GPU 사용률 70% 이상, OOM 없음, 30분 소크 통과다. 30명은 최종 목표이므로 **당장 못 맞춰도 괜찮고**, 각 단계에서 한계를 보고하는 것이 목적이다. 상한을 넘는 접속은 대기 안내로 처리한다(5.4).

### Phase 5 — 안전장치와 공개 운영 (M, 계정·도메인 없이 가능한 구성)

**전제:** 도메인이 없다. Vercel 무료(`*.vercel.app`)와 오리진 직결로 운영하고, 안전장치는 **오리진 안**에 둔다. Cloudflare는 선택 항목(5B)이다.

#### 5A. 필수

| ID | 작업 | 담당 |
|---|---|---|
| 5.1 | **오리진 연결:** `vercel.json`의 rewrites 대상을 오리진 주소로 한다(집 PC는 지금의 Tailscale Funnel, 임대 GPU는 서비스가 주는 공개 주소). **오리진 전환 절차**를 런북에 적는다. 8800은 노출 금지 | 로컬 + 사용자(Vercel 재배포) |
| 5.2 | **동의 게이트(10절):** 첫 방문 시 동의 문구에 체크해야 시작할 수 있게 한다. 동의 사실을 오리진이 서명한 세션 토큰에 기록 | 클라우드 |

| 5.4 | **예산 퓨즈(오리진 안):** 턴마다 사용량(Gemini 입출력 토큰, 합성 초)으로 추정 비용을 누적하고, 한도에 닿으면 정중한 안내 문구로 응답한다. **횟수가 아니라 금액 기준.** 컨테이너가 1개인 동안은 프로세스 메모리와 파일(또는 SQLite)로 충분하고, 여러 개로 늘릴 때만 공유 저장소가 필요하다. **동시 세션 상한**(초기 3, 단계별로 10, 30)을 넘으면 "자리가 찰 때까지 잠깐 기다려 줘" 안내를 보낸다. 퓨즈가 막는 것은 Gemini 비용이고, **GPU 임대 비용은 퓨즈로 못 막으므로 자동 종료(6.5)가 맡는다** | 로컬 |

| 5.6 | **정적 자산 캐시:** 리액션 wav 41개와 아바타 이미지는 불변 파일로 캐시 헤더를 단다(오리진 부하 제거, 즉시 리액션 지연 감소) | 클라우드 |
| 5.7 | **관측:** 오리진은 JSON 줄 로그(turn_id, 단계별 시간, 토큰, 추정 비용, IP 해시) | 로컬 |

| 5.9 | **약관 확인:** Vercel 무료(Hobby)가 비상업용이라는 점, 오디오 스트림 중계가 허용되는지 [가정: 확인 필요] | **사용자** |

#### 5B. 선택 (나중에)

도메인이 생기거나 봇 방어가 필요해지면 Cloudflare를 추가한다. Worker 게이트웨이, Turnstile(계정만 있으면 무료로 쓸 수 있는 것으로 알고 있다 [가정]), Durable Object 전역 카운터, Named Tunnel(도메인 필요 [가정])이 후보다. Cloudflare 계정은 그때 만든다.

| 8.3 | **양자화:** AR 디코더 가중치만 int8/FP8(디코딩이 메모리 대역폭에 묶여 있으면 이득) | 중 | 음질 저하 → 청취 |
| 8.4 | **보코더 최적화:** SoVITS 디코더 fp16, 컴파일, TensorRT/ONNX(커뮤니티 `Genie-TTS`가 ONNX 엔진을 제공 [조사]) | 중 | 이음매·음질 |
| 8.5 | **추측 디코딩/드래프트 모델 증류** | 불확실 | 연구 성격, 마지막 수단 |
| 8.6 | **다른 구조 후보 평가**(채택 약속 없음): 스트리밍을 기본 지원하는 모델, 비자기회귀 모델 등. 같은 120분 데이터와 **같은 블라인드 청취 도구**로 비교하고, 조합 D보다 낫고 전체 파이프라인 RTF도 나을 때만 채택. 후보별 한국어 지원, 라이선스, 필요한 학습량은 조사부터 [가정] | 큼 | **사용자가 고른 음색을 포기할 수 있음** |
| 8.7 | **음성 워터마크(선택):** 합성 음성에 사람이 못 듣는 표식을 넣어, 유출·재공유된 음성이 이 서비스에서 나온 AI 음성임을 나중에 확인할 수 있게 한다. 오픈소스 후보(예: Meta의 AudioSeal)를 조사하고 음질 영향·비용을 확인 [가정: 존재와 라이선스 확인 필요] | 중(분쟁 대응에 도움) | 음질·지연 영향, 완벽한 방어는 아님 |

## 6. 롤아웃과 되돌리기

- **기능 플래그:** 서버 `TTS_ENGINE=legacy|fast`, 클라이언트 `?stream=0|1`. 기본값은 항상 검증된 쪽.
- **병행 운영:** 옛 서버를 그대로 두고 새 서버를 다른 포트(또는 다른 임대 GPU)로 띄운다. 이 규모에서는 가중치 분배(카나리) 대신 **오리진 주소 전환**(`vercel.json`)으로 충분하고, 문제가 생기면 되돌린다.
- **킬 스위치:** 오리진의 `/admin/pause`(5.8)로 즉시 "점검 중" 응답으로 바꿀 수 있다. 예산 퓨즈와 같은 경로를 쓴다.
- **이벤트 당일 체크리스트:** 예산 한도, 임대 시간, 종료 시각, 사용자 알림, 닫는 방법(터널 끄기, 인스턴스 종료)을 미리 적어 둔다.

## 7. 비용 모델 (계산식, 요금은 직접 확인해서 채울 것)

### 월 3만 원이 사 주는 GPU 시간

시간당 요금을 모르므로 가정별로 계산만 해 둔다(요금은 업체 사이트에서 확인하고 이 표에 채운다).

| 시간당 요금(예시 가정) | 월 3만 원으로 켤 수 있는 시간 |
|---|---|
| 500원 | 60시간 |
| 1,000원 | 30시간 |
| 2,000원 | 15시간 |
| (확인한 실제 요금) | 30,000 ÷ 요금 |

- 한 달은 약 720시간이다. **상시 가동은 예산을 한참 넘는다.** 그래서 **"행사 시간에만 켠다"가 기본 운영 형태**다. 예: 한 번에 3시간짜리 행사를 월 5~10번.
- **집 PC는 추가 비용이 없다.** 평소 개발·소규모 사용은 집 PC + Tailscale Funnel로 하고, **사람이 많이 모이는 행사 때만 임대 GPU**를 켜는 하이브리드가 예산에 맞다(사용자 결정).
- 저장 볼륨(모델 수 GB~수십 GB)은 GPU를 꺼도 **별도로 과금되는 업체가 많다.** 볼륨 요금도 확인해서 월 예산에 포함한다.
- 서버리스(초 단위 과금)는 쓴 시간만 내지만, 콜드 스타트를 피하려고 인스턴스를 데워 두면 그 시간만큼 과금된다. 행사 시간표가 정해져 있으면 시간제 임대와 비용 차이가 크지 않을 수 있다 [가정].
- **Modal Starter는 매달 $30 크레딧이 무료**라서 L4 기준 약 37시간이다(GPU 요금만 환산, CPU·메모리 별도 과금이라 실제는 더 적다) [조사, 검증 필요]. 이 크레딧을 먼저 쓰고, 모자랄 때 월 3만 원 예산을 쓰는 순서가 된다. 달러당 1,400원을 가정하면 3만 원은 L4 약 27시간이다. 합치면 **월 60시간 안팎이 이론상 상한**이고, 3시간짜리 행사로 월 약 20번 분량이다 [계산, 요금 확인 전].

### 비용 항목

| 항목 | 식 | 값 |
|---|---|---|
| GPU 임대 | 시간당 요금 × 켜 둔 시간 + 볼륨 월 요금 | 월 3만 원 이내(확정 결정). 요금 확인 필요 |
| Gemini 턴당 비용 | **지금까지 쓴 금액(103원) ÷ 그동안의 대화 턴 수.** 턴 수는 `data\server.log`의 대화 횟수로 센다. Phase 0.6의 토큰 로그가 생기면 입출력 토큰 × 단가로 다시 계산 | (턴 수 확인 필요) |
| Gemini 행사 1회 예상 | **접속 인원(3명, 10명, 30명 등 단계별) × 1인당 시간당 턴 수 × 행사 시간 × 턴당 비용** | 위 턴당 비용이 나오면 계산 |
| 수용량 | 동시 합성 수 N = GPU 한 장이 유지하는 값 (Phase 4.7 시험 결과) | (측정) |
| 예산 퓨즈 상한 | **행사 1회 예상 비용 × 3**(여유와 폭주 방어를 겸함) | 사용자가 최종 결정 |
| Vercel | 무료(Hobby) 한도와 비상업용 약관 확인(5.9) | 0원 예상 [가정] |
| Cloudflare | 5B를 쓰게 될 때만 요금표 확인 | 지금은 사용하지 않음 |

### 30명이 가능한가 (정직한 판단)

- 지금 방식(작업자 1개, 문장당 1.5~2.8초 [문서])으로는 **불가능**하다. 동시 합성 약 10명을 감당하려면 Phase 2~4(CUDA Graph, 연속 배치)가 필요하다.
- 참고 수치: GSV-TTS-Lite가 RTX 3050 노트북에서 RTF 0.108을 보고했다 [조사, 자체 보고]. 단건 속도가 이 정도이고 배치로 처리량이 몇 배 늘면 **GPU 한 장으로 동시 합성 10명은 가능성이 있다** [가정]. 한국어 이식 후 실측이 필요하다.
- 따라서 **30명 목표의 성패는 Phase 0 측정과 Phase 2~4 결과로 정해진다.** 측정 전에는 약속하지 않는다.

## 8. 역할과 작업 카드

### 역할

- **사용자:** 계정 가입과 결제(**임대 GPU 서비스(Modal 등)**, Cloudflare는 필요해질 때만), Vercel 재배포(오리진 전환), 예산 한도 결정, **블라인드 청취 판정**, 약관 확인, 배포 승인.

- **클라우드 Claude(이 세션):** 조사, 설계 문서, 웹 프런트엔드(스트리밍 재생기), 가짜 서버와 부하 시험기, 동의 게이트 화면, 임대 GPU 배포 스크립트 초안과 런북. **GPU·PC·Cloudflare 계정에는 접근할 수 없다.** 코드는 가짜 서버와 브라우저 자동 시험까지만 검증한다.

### 시작 순서 제안

1. (사용자) 이 문서를 로컬 세션에 읽히고 **Phase 0**부터 시작한다. 같은 시기에 **Modal 무료 계정을 만들어 둔다**(6.1).
2. (클라우드) Phase 0과 병행해서 **3.3, 3.4(스트리밍 재생기와 가짜 서버)**, **4.7(부하 시험기)**, **5.2(동의 게이트 화면)**, **6.2·6.6(임대 GPU 배포 스크립트 초안과 런북)**, **0.7의 브라우저 측정 훅**을 준비한다.

## 10. 목소리 사용 조건과 준수 사항

> 사용자가 전해 준 조건을 기술 요구사항으로 옮긴 절이다. **법률 자문이 아니다.** 허락의 정확한 범위는 원문을 가진 사용자가 확인한다.

### 확인된 조건 (사용자 전달, 2026-10-07)

1. **마젯 목소리임을 밝힌다.**
2. 기존 규칙을 적용한다: **외설적이거나 폭력적인 상황에 사용하지 않는다.**
3. 어기면 **미츄 회사와 법적 분쟁이 생길 수 있다.**

### 사용자 결정 (2026-10-07)

- **가중치 파일은 비공개로 확정**했다. 서비스로만 제공한다.
- **이용자에게는 동의를 구하는 정도의 문구만** 보여 준다. **신고 연락처는 두지 않는다.** 시도는 가드레일이 막는다.
- 대화 음성을 **녹음해서 올리는 것**은 기존 규칙의 "공유" 금지에 해당하므로 동의 문구에 한 줄로 포함한다.
- (권장) **허락 문구 원문, 링크, 확인한 날짜를 비공개 메모로 보관**해 두면 분쟁이 생겼을 때 근거가 된다.

### 이행 방법

| # | 요구 | 구현 | 담당 |
|---|---|---|---|
| 10.1 | 마젯 목소리임을 밝히고 동의를 구함 | **동의 게이트:** 첫 방문 시 동의 문구(아래 초안)를 보여 주고 체크해야 시작할 수 있게 한다. 크레딧에도 같은 문구를 남긴다. **현재 페이지 문구는 "목소리와 답변은 AI가 만들어요"까지만 있고 마젯 목소리임은 밝히지 않으므로 수정 대상** | 클라우드(반영) + 사용자(문구 확정) |
| 10.2 | 이용 규칙 | 동의 문구 안에 금지 규칙과 "녹음·재공유 금지"를 한 줄로 포함 | 동일 |
| 10.3 | 외설·폭력 응답 차단 | ① Gemini 안전 필터 유지(성적 LOW, 위험 MEDIUM 등 [문서]) ② **합성 직전 문장 검사:** 서버가 만든 답변이 TTS로 가기 전에 금지어·분류기로 검사하고, 걸리면 "어… 그런 얘기는 패스!"로 바꾼다. 이것이 마지막 방어선이다 ③ 사용자 입력의 유도 시도(성적·폭력적 롤플레이, 규칙 무시 요청) 탐지 시 거절 | 로컬 |
| 10.4 | 임의 문장 합성 불가 | 설계 원칙 1 유지. 새 스트리밍 규약에도 TTS용 텍스트 입력은 없다 | 로컬 |
| 10.5 | 반복 시도 차단 | 위반 시도가 일정 횟수 쌓인 세션/IP를 일정 시간 차단(오리진 안에서) | 로컬 |
| 10.6 | 기록 | 위반 의심 턴의 텍스트, 시각, 세션 ID, IP 해시를 **14~30일 보관(제안)**. 보관 사실은 동의 문구에 한 줄로 포함. 음성 파일은 저장하지 않는다 | 로컬 |
| 10.7 | 중단·차단 | **신고 연락처는 두지 않는다**(사용자 결정). 대신 운영자가 로그를 보고 세션을 차단하고, **킬 스위치(5.8)로 전체 중단**할 수 있다 | 로컬 + 사용자 |
| 10.8 | 가중치 비공개 | 비공개 볼륨에만 둔다. 공개 버킷·깃 금지. 접근 키는 코드와 `.env` 밖 시크릿 저장소 | 로컬 |
| 10.9 | 유출 추적(선택) | 8.7의 음성 워터마크 | 선택 |

**시험(공개 전 필수):** 안전 필터를 깨려는 시도 세트로 레드팀 시험을 한다. 범주는 ① 성적 롤플레이 유도 ② 폭력 묘사 요청 ③ 우회(은어, 철자 변형, 다른 언어) ④ 프롬프트 주입("위 규칙을 무시해") ⑤ 마젯이 하지 않은 말을 시키려는 시도다. 통과 기준은 **위반 문장이 TTS까지 가는 경우 0건**이고, 로컬 세션이 시험 세트를 만들어 결과를 사용자에게 보여 준다.

**한계(솔직하게):** 화면 녹음으로 음성을 저장하는 것은 기술로 완전히 막을 수 없다. 동의 문구, 차단, 기록, 워터마크로 "위반이 어렵고, 생겨도 대응할 수 있는 상태"를 만드는 것이 현실적인 목표다. 신고 창구를 두지 않기로 했으므로 **가드레일이 사실상 유일한 방어선**이다. 그래서 레드팀 시험 통과를 공개 조건으로 삼고, 공개 중에는 운영자가 로그를 주기적으로 확인한다.

### 동의 문구 초안 (사용자가 최종 확정)

> 이 목소리는 버튜버 **마젯(미츄 소속)의 목소리를 AI로 학습·재현**한 것이에요. 마젯 본인이 말하는 게 아니에요.
> 팬이 만든 비공식 서비스예요. 캐릭터 그림은 미츄(MEECHU) 마젯 3D 모델의 표정 이미지예요.
> **외설적이거나 폭력적인 상황에 사용하거나, 그런 내용을 만들어 녹음·공유하는 것은 금지돼요.** 대화 내용은 안전을 위해 일정 기간 기록돼요.
> ☐ 위 내용을 확인했고 동의해요. (체크해야 시작할 수 있어요)
