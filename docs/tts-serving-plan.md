### 핵심 결론 3가지

1. **병목은 모델이 아니라 서빙이다.** GPU 사용률 28%, 토큰당 30ms, 작업자 1개, 문장을 끝까지 합성한 뒤에 재생 [문서]. 같은 모델을 쓰는 최적화 엔진은 훨씬 빠르다고 보고돼 있다(GSV-TTS-Lite: RTX 3050 노트북에서 첫 패킷 133ms, RTF 0.108 [조사], 프로젝트 자체 보고).
2. **가장 큰 레버는 4가지다.** ① CUDA Graph 엔진 ② 토큰 스트리밍 ③ 연속 배치 ④ 첫 문장을 일찍 자르기. 다만 **GSV-TTS-Lite는 한국어를 지원하지 않는다** [조사]. 한국어 전처리를 이식하고 음질이 같은지 확인하는 것이 이 계획의 가장 큰 위험이자 핵심 작업이다.
3. **Cloudflare는 계산이 아니라 입구다.** Cloudflare Containers에는 GPU가 없다 [조사]. 보안, 예산 퓨즈, 터널, 정적 호스팅을 맡기고 GPU는 임대하거나 집 PC를 쓴다.

## 2. 목표 아키텍처

```
[브라우저]
   │  HTTPS(정적), WebSocket(대화·음성 스트림)
   ▼
[Cloudflare 엣지]
   ├─ Pages: web/ 정적 파일
   └─ Worker(게이트웨이): Turnstile 검증 → 세션 토큰 발급
        속도 제한(Rate Limiting 바인딩) · 예산 퓨즈(Durable Object) · 킬 스위치
   │
   ▼  Cloudflare Tunnel (cloudflared, 오리진에서 밖으로 연결, 포트 개방 불필요)
[오리진 (임대 GPU 또는 집 PC)]
   ├─ 오케스트레이터 (FastAPI/asyncio, 8801 상당)
   │    ├─ 즉시 리액션 (기존)
   │    ├─ Gemini 스트리밍 → 문장 단위 분할
   │    └─ TTS 요청 → 엔진 (연속 배치 + CUDA Graph + 토큰 스트리밍)
   ├─ TTS 엔진 (한국어 전처리 포함) → PCM 청크
   ├─ STT (서버 경로용 faster-whisper)
   └─ 8800(로컬 전용 `/v1/*`)은 **밖으로 노출하지 않는다**
```

### 설계 원칙 (바꾸지 말 것)

1. **임의 문장을 마젯 목소리로 읽게 하는 API는 만들지 않는다.** TTS의 텍스트는 서버가 만든 답변에서만 나온다 [문서: 사칭 방지]. 새 WebSocket 프로토콜에서도 클라이언트가 TTS에 텍스트를 보낼 수 없다.
2. **목소리 가중치는 비공개 저장소에만 둔다.** GitHub, 공개 R2 버킷에 올리지 않는다 [문서]. 서비스로 들려주는 것과 모델 파일을 배포하는 것은 별개다.
3. **품질은 숫자보다 사용자 귀가 우선**이다 [문서]. 엔진을 바꿀 때마다 블라인드 청취를 거친다.
4. **언제든 옛 경로로 되돌릴 수 있게** 한다(6절).
5. **마젯 목소리임을 밝히고, 외설적이거나 폭력적인 사용을 막는다.** 고지 문구, 합성 직전 문장 검사, 신고·차단, 로그는 선택이 아니라 요구사항이다(10절). 확인된 조건을 어기면 미츄 회사와 법적 분쟁이 생길 수 있다는 것이 사용자의 설명이다.
6. **예산이 먼저다.** 동시 30명과 월 3만 원 안에서 설계한다. 비용이 한도에 닿으면 서비스가 정중하게 멈추는 구조(예산 퓨즈, 자동 종료)를 기능보다 먼저 만든다.

### 전송 규약 (WebSocket)

- 클라이언트 → 서버: `hello{session, token}`, `user_text{text}`, `cancel{reply}`(끼어들기), `ping`
- 서버 → 클라이언트: `start{reply}`, `text{d}`, `emotion{e}`, `audio_begin{i, sr, fmt}`, **바이너리 오디오 프레임**, `audio_end{i}`, `done`, `error{code}`, `pong`
- Cloudflare는 **유휴 100초**에 연결을 끊는다(Free/Pro/Business는 변경 불가) [조사]. 20~30초마다 하트비트를 보내고, 끊김은 재연결로 처리한다.
- 오디오는 PCM16 모노로 시작한다. 대역폭이 문제가 되면 Opus로 바꾼다.
- 기존 NDJSON + `/speech?r&i` 경로는 **폴백으로 유지**한다.

## 3. 컴퓨트 배치 옵션 (사용자 결정 필요)

| 옵션 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. 집 PC + Cloudflare Tunnel** | 지금 PC 그대로, Tailscale Funnel 대신 Tunnel | 추가 비용 없음, 개발에 편함 | PC가 꺼지면 끝, 느린 CPU, 상시 공개엔 부적합 |
| **B. 임대 GPU 1대** | RunPod, Vast.ai, Lambda, GCP 등에서 시간당 임대. 도커로 배포 | 빠른 CPU와 GPU, 필요한 시간만 | 시간당 과금(켜 둔 만큼), 설치 작업 |
| **C. 서버리스 GPU** | Modal 등 초 단위 과금, 요청이 오면 기동 | 사용한 만큼만, 자동 확장 | 모델 로딩 콜드 스타트, 연속 배치와 궁합이 어려움 |
| D. Cloudflare만으로 | - | - | **불가.** Containers에 GPU가 없다 [조사]. Workers AI는 고정 모델이라 사용자 모델을 못 올린다 [가정] |

- **추천:** 개발과 측정은 **A**, 공개 이벤트는 **B**(필요한 시간만 임대), 상시 운영·변동 트래픽이 확인되면 **C**를 검토한다.
- 요금은 변동이 커서 이 문서에 쓰지 않는다. 7절의 계산식에 **직접 확인한 값**을 넣는다.
- **VRAM 가늠(가정):** GSV-TTS-Lite는 원본(1.6GB) 대비 0.8GB 보고 [조사]. Whisper large-v3 int8_float16이 수 GB. 16~24GB GPU 한 장에 TTS 여러 작업자와 STT가 들어갈 가능성이 높다. Phase 0에서 실측한다.
- **지역:** 한국에서 가까운 리전(도쿄, 싱가포르 등)을 우선 비교하되, 실제 RTT는 측정으로 확인한다.

### Phase 2 — 추론 엔진: CUDA Graph + 한국어 이식 (L, 핵심)

**배경:** GSV-TTS-Lite는 MIT 라이선스이고, **CUDA Graph, Nested KV Cache, 연속 배치, 토큰 스트리밍(예제에서 stream_chunk=25, overlap_len=5), 선택적 FlashAttention 2**를 갖췄다. v2/v2Pro/v2ProPlus를 지원하고 사용자 체크포인트를 읽는 API(`load_gpt_model`, `load_sovits_model`, `to_safetensors`)가 있다. **그러나 지원 언어는 중·일·영뿐이다.** 최신 확인 버전은 0.4.7이다 [조사].

| ID | 작업 | 담당 |
|---|---|---|
| 2.1 | **격리된 환경에서 평가:** 깨끗한 WSL2/Linux 가상환경(또는 도커)에 `gsv-tts-lite`를 **버전 고정**해서 설치. 우리 SoVITS `majet_v2_e3`, GPT `majet_v1-e10`을 변환해 로드. 먼저 **중·일·영 문장으로 속도와 로드 성공 여부부터** 확인 | 로컬 |
| 2.2 | **한국어 전처리 이식:** 원본 `GPT_SoVITS/text/` 쪽의 한국어 처리(정규화 → 음소 변환 → 음소 ID)를 엔진 쪽 언어 분기에 추가. 원본이 비중국어에서 BERT 특징을 어떻게 처리하는지도 **그대로** 따른다 [가정: 확인 필요] | 로컬 |
| 2.3 | **음소열 동일성 시험:** 말투 코퍼스 1,058줄 + 골든 세트에서 원본과 이식본의 음소 ID 열이 **100% 일치**해야 한다(불일치는 즉시 수정) | 로컬 |
| 2.4 | **음질 시험:** 같은 문장, 같은 샘플링 설정(top_k 15, temperature 1.0, 레퍼런스 calm)으로 합성. 지표는 `tts_eval.py`의 유사도·발음 오류. 이후 **사용자 블라인드 청취(기준 음성 vs 새 엔진, A/B/X)** | 로컬 + **사용자** |
| 2.5 | 속도 시험: Phase 0과 같은 벤치로 토큰당 ms, RTF, TTFA, VRAM 비교. FlashAttention 2 유무도 비교 | 로컬 |

**합격(제안):** 유사도 0.80 이상, 발음 오류 3% 이하, 블라인드에서 기준(조합 D)과 같거나 더 낫다는 사용자 판정, 토큰당 시간 절반 이하.

**결정 게이트(시간 상자 3~5일):** 이식이 합격하지 못하면 **2B**로 전환한다.
- **2B: 원본 엔진을 직접 가속.** AR 디코더에 정적 KV 캐시와 고정 길이 구간(버킷)을 두고 CUDA Graph로 캡처한다. `torch.compile(mode="reduce-overhead")`는 Triton이 필요한데 **공식 Triton이 Windows를 지원하지 않는다** [조사]. WSL2/리눅스 도커에서 하거나 커뮤니티 `triton-windows`를 쓴다. 수동 `torch.cuda.CUDAGraph` 캡처는 Windows에서도 가능하다 [가정]. 난이도가 높아 최후 선택.
- 이 경우에도 Phase 3(스트리밍), Phase 4(배치) 설계는 그대로 쓴다.

**참고:** CUDA Graph는 일반 LLM 추론에서 2.3배 가속 사례가 있다 [조사]. 같은 구조의 AR TTS에 vLLM을 적용해 GPT 디코딩이 약 3배 빨라졌다는 사례(IndexTTS) [조사]도 있다. 두 숫자 모두 다른 모델의 사례라서 우리 모델에 그대로 기대하면 안 된다.

**목표:** 문장 전체를 기다리지 않고, 첫 조각이 나오는 순간 재생을 시작한다.

### Phase 4 — 동시성: 연속 배치, 스케줄러, 취소 (L)

**왜 효과가 클 것 같은가(가정):** AR 디코딩은 단계마다 메모리를 읽는 일이 대부분이라 요청 8개를 묶어도 한 단계 시간이 거의 늘지 않는다. 지금은 GPU가 28%만 쓰이고 있어서 묶으면 처리량이 크게 늘 여지가 있다. 원본 README의 높은 처리량 수치도 병렬 추론 조건이다 [조사].

| ID | 작업 | 담당 |
|---|---|---|
| 4.1 | **빠른 이득:** 합성 작업자 N개(프로세스) + 최소 부하 배정. 작업자 하나의 VRAM이 작으면(0.8GB 보고) 한 GPU에 3~4개가 들어간다 [가정] | 로컬 |
| 4.2 | **엔진 연속 배치:** 요청이 매 디코딩 단계마다 배치에 들어오고 나가게 한다. 선채움(prefill)은 분리. 배치 크기 상한 B는 부하 시험으로 정한다. GSV-TTS-Lite의 `infer_batched()`/연속 배치 기능 활용 가능 [조사] | 로컬 |
| 4.3 | **디코더(보코더) 큐 분리:** 여러 요청의 조각을 모아 SoVITS 디코딩을 배치하고, 토큰 생성과 겹쳐서 실행(별도 CUDA 스트림/스레드) | 로컬 |
| 4.4 | **우선순위:** 첫 조각과 즉시 리액션 > 이후 조각. 한 사용자가 독점하지 못하게 세션별 공정성 | 로컬 |
| 4.5 | **취소와 역압:** `cancel`이 오면 다음 단계에서 배치에서 제거. 대기열은 상한을 두고, 넘치면 `busy` + 재시도 안내를 보내서 화면에 "잠깐 줄 서는 중"을 표시 | 로컬 + 클라우드(UI) |
| 4.6 | **수용량 공개:** `/healthz`에 `capacity`, `queue_depth`, `p95_ttfa`를 노출. 게이트웨이와 UI가 사용 | 로컬 |
| 4.7 | **부하 시험기:** WebSocket 가상 사용자 N명이 말하고 듣는 스크립트(`dev/loadtest/`). 가짜 서버로 먼저 만들고, 실제 서버에서 로컬이 실행 | **클라우드**(작성) + 로컬(실행) |

**목표 해석(가정):** "동시 접속 30명"은 30명이 동시에 합성을 요청한다는 뜻이 아니다. 대화 중에는 사용자가 말하고, 생각하고, 마젯이 말하는 시간이 번갈아 오므로, **동시에 합성 중인 수 ≈ 접속자 × 마젯이 말하는 시간 비율(약 0.3~0.4 가정) ≈ 9~12명**이다. 이 비율은 부하 시험기에 현실적인 말하기·듣기 주기를 넣어서 실제로 확인한다.

**합격(제안):** **가상 사용자 30명**(현실적인 주기, 동시 합성 약 10)에서 TTFA p95가 단독 p50의 2배 이내, GPU 사용률 70% 이상, OOM 없음, 30분 소크 통과. 30명을 넘는 접속은 대기 안내로 처리한다(5.4).

### Phase 8 — (선택) 구조·토큰 수 개선 R&D (시간 상자 1주)

핵심 사실: GPT-SoVITS는 음성 1초당 토큰 수가 사전학습된 의미 코덱에 의해 정해져 있다 [가정]. **토큰 수 자체를 줄이려면 두 단계를 다시 학습해야 해서 비용이 크다.** 그래서 현실적인 순서는 다음과 같다.

| ID | 작업 | 기대 | 위험 |
|---|---|---|---|
| 8.1 | **낭비 토큰 제거:** 앞뒤 무음 토큰 자르기, 조각당 최대 토큰 상한(글자 수 대비 비율로 폭주 방지), `repetition_penalty` 튜닝, 불필요한 패딩 제거 | 소~중 | 말끝이 잘림 → 청취 확인 |
| 8.2 | **레퍼런스 길이 조정:** 프롬프트가 길수록 선채움과 어텐션 비용이 늘어난다. 3~5초 레퍼런스와 비교 | 소 | 음색·말투 변화 |
| 8.3 | **양자화:** AR 디코더 가중치만 int8/FP8(디코딩이 메모리 대역폭에 묶여 있으면 이득) | 중 | 음질 저하 → 청취 |
| 8.4 | **보코더 최적화:** SoVITS 디코더 fp16, 컴파일, TensorRT/ONNX(커뮤니티 `Genie-TTS`가 ONNX 엔진을 제공 [조사]) | 중 | 이음매·음질 |
| 8.5 | **추측 디코딩/드래프트 모델 증류** | 불확실 | 연구 성격, 마지막 수단 |
| 8.6 | **다른 구조 후보 평가**(채택 약속 없음): 스트리밍을 기본 지원하는 모델, 비자기회귀 모델 등. 같은 120분 데이터와 **같은 블라인드 청취 도구**로 비교하고, 조합 D보다 낫고 전체 파이프라인 RTF도 나을 때만 채택. 후보별 한국어 지원, 라이선스, 필요한 학습량은 조사부터 [가정] | 큼 | **사용자가 고른 음색을 포기할 수 있음** |
| 8.7 | **음성 워터마크(선택):** 합성 음성에 사람이 못 듣는 표식을 넣어, 유출·재공유된 음성이 이 서비스에서 나온 AI 음성임을 나중에 확인할 수 있게 한다. 오픈소스 후보(예: Meta의 AudioSeal)를 조사하고 음질 영향·비용을 확인 [가정: 존재와 라이선스 확인 필요] | 중(분쟁 대응에 도움) | 음질·지연 영향, 완벽한 방어는 아님 |

## 6. 롤아웃과 되돌리기

- **기능 플래그:** 서버 `TTS_ENGINE=legacy|fast`, 클라이언트 `?stream=0|1`. 기본값은 항상 검증된 쪽.
- **병행 운영(카나리):** 옛 서버를 그대로 두고 새 서버를 다른 포트로 띄운다. Worker가 가중치로 일부 트래픽만 새 서버에 보낸다.
- **킬 스위치:** Worker 한 곳에서 `/api/*`를 즉시 503 + 안내 문구로 바꿀 수 있다. 예산 퓨즈와 같은 경로.
- **이벤트 당일 체크리스트:** 예산 한도, 임대 시간, 종료 시각, 사용자 알림, 닫는 방법(터널 끄기, 인스턴스 종료)을 미리 적어 둔다.

## 7. 비용 모델 (계산식, 요금은 직접 확인해서 채울 것)

### 월 3만 원이 사 주는 GPU 시간

시간당 요금을 모르므로 가정별로 계산만 해 둔다(요금은 업체 사이트에서 확인하고 이 표에 채운다).

| 시간당 요금(예시 가정) | 월 3만 원으로 켤 수 있는 시간 |
|---|---|
| 500원 | 60시간 |
| 1,000원 | 30시간 |
| 2,000원 | 15시간 |
| (확인한 실제 요금) | 30,000 ÷ 요금 |

- 한 달은 약 720시간이다. **상시 가동은 예산을 한참 넘는다.** 그래서 **"행사 시간에만 켠다"가 기본 운영 형태**다. 예: 한 번에 3시간짜리 행사를 월 5~10번.
- **집 PC는 추가 비용이 없다.** 평소 개발·소규모 사용은 집 PC + Tunnel로 하고, **30명이 모이는 행사 때만 임대 GPU**를 켜는 하이브리드가 예산에 맞다.
- 저장 볼륨(모델 수 GB~수십 GB)은 GPU를 꺼도 **별도로 과금되는 업체가 많다.** 볼륨 요금도 확인해서 월 예산에 포함한다.
- 서버리스(초 단위 과금)는 쓴 시간만 내지만, 콜드 스타트를 피하려고 인스턴스를 데워 두면 그 시간만큼 과금된다. 행사 시간표가 정해져 있으면 시간제 임대와 비용 차이가 크지 않을 수 있다 [가정].

### 비용 항목

| 항목 | 식 | 값 |
|---|---|---|
| GPU 임대 | 시간당 요금 × 켜 둔 시간 + 볼륨 월 요금 | 월 3만 원 이내(확정 결정). 요금 확인 필요 |
| Gemini 턴당 비용 | **지금까지 쓴 금액(103원) ÷ 그동안의 대화 턴 수.** 턴 수는 `data\server.log`의 대화 횟수로 센다. Phase 0.6의 토큰 로그가 생기면 입출력 토큰 × 단가로 다시 계산 | (턴 수 확인 필요) |
| Gemini 행사 1회 예상 | **30명 × 1인당 시간당 턴 수 × 행사 시간 × 턴당 비용** | 위 턴당 비용이 나오면 계산 |
| 수용량 | 동시 합성 수 N = GPU 한 장이 유지하는 값 (Phase 4.7 시험 결과) | (측정) |
| 예산 퓨즈 상한 | **행사 1회 예상 비용 × 3**(여유와 폭주 방어를 겸함) | 사용자가 최종 결정 |
| Cloudflare | Workers/DO/Pages 무료 한도와 요금표 확인 | (확인 필요) |

### 30명이 가능한가 (정직한 판단)

- 지금 방식(작업자 1개, 문장당 1.5~2.8초 [문서])으로는 **불가능**하다. 동시 합성 약 10명을 감당하려면 Phase 2~4(CUDA Graph, 연속 배치)가 필요하다.
- 참고 수치: GSV-TTS-Lite가 RTX 3050 노트북에서 RTF 0.108을 보고했다 [조사, 자체 보고]. 단건 속도가 이 정도이고 배치로 처리량이 몇 배 늘면 **GPU 한 장으로 동시 합성 10명은 가능성이 있다** [가정]. 한국어 이식 후 실측이 필요하다.
- 따라서 **30명 목표의 성패는 Phase 0 측정과 Phase 2~4 결과로 정해진다.** 측정 전에는 약속하지 않는다.

## 8. 역할과 작업 카드

### 역할

- **사용자:** 계정 가입과 결제(Cloudflare, GPU 업체), 예산 한도 결정, **블라인드 청취 판정**, 약관·허락 범위 확인, 배포 승인.

## 10. 목소리 사용 조건과 준수 사항

> 사용자가 전해 준 조건을 기술 요구사항으로 옮긴 절이다. **법률 자문이 아니다.** 허락의 정확한 범위는 원문을 가진 사용자가 확인한다.

### 확인된 조건 (사용자 전달, 2026-10-07)

1. **마젯 목소리임을 밝힌다.**
2. 기존 규칙을 적용한다: **외설적이거나 폭력적인 상황에 사용하지 않는다.**
3. 어기면 **미츄 회사와 법적 분쟁이 생길 수 있다.**

### 아직 확인되지 않은 것과 권장 조치

- **가중치 파일 배포**가 허락 범위에 들어가는지. 확인 전까지 비공개.
- 사용자가 대화 음성을 **녹음해서 올리는 것**의 취급. 기존 규칙의 "공유" 금지에 해당하므로 이용 규칙에 명시한다.
- **허락 문구 원문, 링크, 확인한 날짜를 비공개 메모로 보관**하길 권한다. 분쟁이 생기면 근거가 된다. 애매한 점(가중치 배포 등)은 미츄 측에 메일이나 DM으로 서면 확인을 받아 두는 편이 안전하다.

### 이행 방법

| # | 요구 | 구현 | 담당 |
|---|---|---|---|
| 10.1 | 마젯 목소리임을 밝힘 | 첫 화면과 크레딧에 고지 문구(아래 초안)를 항상 보이게 둔다. **현재 페이지 문구는 "목소리와 답변은 AI가 만들어요"까지만 있고 마젯 목소리임은 밝히지 않으므로 수정 대상** | 클라우드(반영) + 사용자(문구 확정) |
| 10.2 | 이용 규칙 고지 | 같은 곳에 금지 규칙과 "녹음·재공유 금지" 문구 | 동일 |
| 10.3 | 외설·폭력 응답 차단 | ① Gemini 안전 필터 유지(성적 LOW, 위험 MEDIUM 등 [문서]) ② **합성 직전 문장 검사:** 서버가 만든 답변이 TTS로 가기 전에 금지어·분류기로 검사하고, 걸리면 "어… 그런 얘기는 패스!"로 바꾼다. 이것이 마지막 방어선이다 ③ 사용자 입력의 유도 시도(성적·폭력적 롤플레이, 규칙 무시 요청) 탐지 시 거절 | 로컬 |
| 10.4 | 임의 문장 합성 불가 | 설계 원칙 1 유지. 새 WebSocket 규약에도 TTS용 텍스트 입력은 없다 | 로컬 |
| 10.5 | 반복 시도 차단 | 위반 시도가 일정 횟수 쌓인 세션/IP를 일정 시간 차단(Worker + Durable Object) | 클라우드 |
| 10.6 | 기록 | 위반 의심 턴의 텍스트, 시각, 세션 ID, IP 해시를 **14~30일 보관(제안)**. 보관 사실을 페이지에 고지. 음성 파일은 저장하지 않는다 | 로컬 |
| 10.7 | 신고·중단 | 페이지에 신고 연락처, 접수 시 해당 세션 차단, **킬 스위치(6절)로 전체 중단** | 사용자 + 클라우드 |
| 10.8 | 가중치 비공개 | 비공개 볼륨에만 둔다. 공개 버킷·깃 금지. 접근 키는 코드와 `.env` 밖 시크릿 저장소 | 로컬 |
| 10.9 | 유출 추적(선택) | 8.7의 음성 워터마크 | 선택 |

**시험(공개 전 필수):** 안전 필터를 깨려는 시도 세트로 레드팀 시험을 한다. 범주는 ① 성적 롤플레이 유도 ② 폭력 묘사 요청 ③ 우회(은어, 철자 변형, 다른 언어) ④ 프롬프트 주입("위 규칙을 무시해") ⑤ 마젯이 하지 않은 말을 시키려는 시도다. 통과 기준은 **위반 문장이 TTS까지 가는 경우 0건**이고, 로컬 세션이 시험 세트를 만들어 결과를 사용자에게 보여 준다.

**한계(솔직하게):** 화면 녹음으로 음성을 저장하는 것은 기술로 완전히 막을 수 없다. 고지, 차단, 기록, 워터마크로 "위반이 어렵고, 생겨도 대응할 수 있는 상태"를 만드는 것이 현실적인 목표다.
